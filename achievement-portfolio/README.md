# 📘 ملف الإنجاز الإلكتروني

تطبيق ويب عربي (RTL) لمعلم جامعي:
- **الطلاب**: يفتحون الرابط، يختارون أسماءهم من قائمة مجمّعة حسب الفصل، يرفعون أعمالهم (ملف أو تصوير بالكاميرا) في 10 خانات، ويتابعون درجاتهم.
- **المعلم**: لوحة تحكم كاملة برمز سري.
- **المدير**: يرى لوحة المعلم كاملة ويفتح الملفات ويطبع الكشوف، **دون أي تعديل** (يرفض الخادم كل تعديل منه).

التقنية: Node.js + Express، قاعدة SQLite (better-sqlite3)، واجهة HTML/CSS/JS بلا خطوة بناء.

## 1) التشغيل المحلي

المتطلبات: Node.js 20 أو أحدث.

```bash
cd achievement-portfolio
npm install
cp .env.example .env      # ثم افتح .env وضع قيمك (انظر القسم التالي)
npm run dev               # يقرأ .env تلقائيًا
```

افتح المتصفح على `http://localhost:3000`:

| الصفحة | الرابط |
|---|---|
| الطلاب (اختيار الاسم) | `/` |
| لوحة الطالب | `/student` |
| لوحة المعلم / المدير | `/admin` |
| كشف الطباعة | `/print` |

> لتجربة الواجهات ببيانات **وهمية** (فصلان و6 طلاب): ضع `SEED_DEMO=1` في `.env` على **قاعدة فارغة**. هذا الخيار معطّل افتراضيًا، ولا تستخدمه مع البيانات الحقيقية.

## 2) ضبط المتغيرات

كل القيم السرية تُقرأ من **متغيرات البيئة فقط**، ولا توجد أي قيمة سرية في الكود.

| المتغير | إلزامي | الوصف |
|---|---|---|
| `ADMIN_PIN` | نعم | رمز دخول المعلم. إن لم يُضبط يُعطَّل دخول المعلم. |
| `MANAGER_PIN` | نعم | رمز دخول المدير (اطلاع فقط). اجعله مختلفًا عن رمز المعلم. |
| `SESSION_SECRET` | نعم في الإنتاج | نص عشوائي طويل لتوقيع الجلسات. التطبيق **يرفض التشغيل** بدونه عند `NODE_ENV=production`. |
| `MAX_FILE_MB` | لا | الحد الأقصى لحجم الملف بالميجابايت (الافتراضي 20). يمكن تغييره لاحقًا من الإعدادات. |
| `DATA_DIR` | لا | مجلد البيانات: قاعدة `app.db` ومجلد `uploads`. يجب أن يكون على **قرص دائم**. |
| `PORT` | لا | المنفذ (الافتراضي 3000). أغلب الاستضافات تضبطه تلقائيًا. |
| `NODE_ENV` | لا | اجعله `production` عند النشر. |
| `SEED_DEMO` | لا | `1` لإدخال بيانات وهمية للتجربة. الافتراضي معطّل. |

توليد سر عشوائي للجلسات:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

**كيف يُحمى الرمز؟** عند الإقلاع يُجزَّأ كل رمز بخوارزمية `scrypt` مع ملح عشوائي، ويُحذف النص الصريح من الذاكرة ومن بيئة العملية. المقارنة تتم بزمن ثابت. بعد **5 محاولات خاطئة** من العنوان نفسه يُقفل الدخول **15 دقيقة**.

## 3) النشر مع قرص دائم

التطبيق يحفظ قاعدة البيانات والملفات على القرص، لذلك **يلزم قرص دائم (Persistent Disk / Volume)** يُركَّب على المسار `DATA_DIR`. بدونه تضيع البيانات عند كل إعادة تشغيل.

### الطريقة أ: Docker (أي استضافة تدعم الحاويات)

```bash
docker build -t achievement-portfolio .
docker run -d --name portfolio -p 3000:3000 \
  -e ADMIN_PIN=... -e MANAGER_PIN=... -e SESSION_SECRET=... \
  -v portfolio-data:/data \
  achievement-portfolio
```

الصورة تضبط `DATA_DIR=/data` و`NODE_ENV=production`، وتعمل بمستخدم غير جذري.

### الطريقة ب: Render
1. **New → Web Service** واربطه بالمستودع، و**Root Directory**: `achievement-portfolio`.
2. **Runtime**: Docker (يستخدم `Dockerfile` الجاهز). أو Node مع: Build `npm ci --omit=dev` وStart `npm start`.
3. **Disks → Add Disk**: Mount Path = `/data`، الحجم 1–5 GB حسب الحاجة.
4. **Environment**: أضف `ADMIN_PIN` و`MANAGER_PIN` و`SESSION_SECRET` (و`DATA_DIR=/data` إذا لم تستخدم Docker).
5. انشر. الرابط سيكون بالشكل `https://<اسم-الخدمة>.onrender.com`.

> ملاحظة: الأقراص الدائمة في Render تتطلب خطة مدفوعة. البدائل التي تدعم الأقراص الدائمة: **Railway** (Volumes) و**Fly.io** (Volumes)، والخطوات نفسها: ركّب القرص على `/data` وأضف المتغيرات الثلاثة.

### بعد النشر
- النسخ الاحتياطي: انسخ مجلد `DATA_DIR` كاملًا (`app.db` و`uploads/`).
- التطبيق يفترض أنه خلف وكيل الاستضافة (`trust proxy`) ليعرف عنوان الزائر ويفعّل الكوكي الآمن على HTTPS.

## 4) رابط النشر

**لم يُنشر التطبيق بعد.** النشر يحتاج حسابك على الاستضافة وقيمك السرية، ولا يتم إلا بعد موافقتك. بعد النشر ضع الرابط هنا:

```
رابط الطلاب:        https://<نطاقك>/
لوحة المعلم/المدير:  https://<نطاقك>/admin
```

شارك مع الطلاب الرابط الأول فقط.

## 5) إضافة الفصول والطلاب من لوحة المعلم

1. افتح `/admin`، واختر **المعلم**، وأدخل الرمز `ADMIN_PIN`.
2. اضغط زر **＋ الفصول والطلاب**.

### إضافة فصل
تبويب **الفصول** ← اكتب اسم الفصل ← **إضافة فصل**. من القائمة نفسها يمكنك **تعديل** اسم الفصل أو **حذفه**. حذف الفصل يحذف طلابه وملفاتهم بعد رسالة تأكيد.

### إضافة الطلاب (4 طرق)
في تبويب **إضافة طلاب** اختر **الفصل** أولًا، ثم إحدى الطرق:

| الطريقة | الخطوات |
|---|---|
| **اسم واحد** | اكتب الاسم ← إضافة. |
| **لصق قائمة** | الصق الأسماء (كل اسم في سطر) ← **معاينة القائمة** ← راجع ← **اعتماد وحفظ**. |
| **ملف CSV / Excel** | اختر ملف `.csv` أو `.xlsx`. يُقرأ عمود **الاسم** (أو «اسم الطالب» أو `name`)، وعمود **الفصل** إن وُجد (أو «الشعبة» أو `class`). الفصول غير الموجودة تُنشأ تلقائيًا، والصفوف التي لا فصل لها تذهب للفصل المختار. يُعرض كل شيء للمراجعة قبل الحفظ. |
| **الكاميرا (OCR)** | **تصوير الكشف** (أو **اختيار صورة**) لكشف أسماء ورقي ← يقرأ المتصفح الأسماء بالعربية ← تظهر في قائمة قابلة للتعديل ← صحّحها ← **اعتماد وحفظ**. |

> ⚠️ **دقة OCR العربي محدودة.** راجع كل اسم قبل الاعتماد، ولن يُحفظ شيء قبل ضغطك «اعتماد وحفظ». للحصول على أفضل نتيجة: إضاءة جيدة، وصورة مستقيمة، وخط مطبوع واضح. أول استخدام يحمّل ملف اللغة العربية (≈1.6 م.ب) من `cdn.jsdelivr.net`، لذا يلزم اتصال بالإنترنت.

مثال ملف CSV:

```csv
الاسم,الفصل
محمد أحمد,شعبة 101
سارة خالد,شعبة 102
```

**الأسماء المكررة:** إذا وُجد الاسم نفسه في الفصل نفسه (مسبقًا أو داخل القائمة) يُظلَّل بالذهبي، وتظهر رسالة تنبيه قبل الحفظ. يمكنك التعديل، أو المتابعة رغم التكرار.

### تعديل طالب أو نقله أو حذفه
اضغط على اسم الطالب في الجدول ليفتح **الدرج الجانبي**، وفي أسفله: **حفظ الاسم** و**نقل للفصل** و**حذف الطالب**. يظهر قبل الحذف تأكيد يوضح أن ملفاته ودرجاته ستُحذف معه.

## 6) الإعدادات والكشوف

- **الإعدادات** (المعلم فقط):
  - الموعد النهائي بتاريخ ووقت **الرياض**، مع أزرار تمديد سريعة (يوم، 3 أيام، أسبوع) أو إلغاء الموعد. بعد الموعد يرفض الخادم الرفع والحذف، ويبقى العرض والتحميل متاحَين.
  - **فتح الرفع لطالب معيّن** بعد الموعد، دون حد أو حتى تاريخ تختاره.
  - الحد الأقصى لحجم الملف.
- **رفض أو خصم عمل**: من درج الطالب اضغط **رفض / خصم** واكتب سببًا اختياريًا. تصبح درجة العمل 0، ويظهر السبب للطالب. يمكن **إلغاء الرفض**.
- **الكشوف والتصدير**: اختر فصلًا أو كل الفصول، ثم:
  - **طباعة / PDF**: كشف رسمي A4 بتنسيق RTL، فيه اسم الفصل ورقم الطالب واسمه وعدد الإضافات والدرجة من 10 وتاريخ الطباعة، وكل فصل في صفحة. لحفظه PDF اختر «حفظ بتنسيق PDF» في نافذة الطباعة.
  - **تصدير Excel**: ملف `.xlsx` بورقة لكل فصل واتجاه من اليمين لليسار.

### قواعد الدرجات
- 10 خانات، وكل عمل مرفوع ومقبول = درجة واحدة، والحد الأقصى 10.
- حذف العمل يعيد الخانة فارغة وتنقص الدرجة.
- الرفض يجعل درجة العمل 0 مع بقاء الخانة مشغولة.
- **نسبة الإنجاز** = عدد الأعمال المرفوعة ÷ 10، و**المكتمل** هو من رفع 10 أعمال.

## 8) ملاحظات أمنية

- **الطالب** لا يحتاج كلمة مرور (حسب التصميم: اختيار الاسم فقط). جلسته مرتبطة بالطالب الذي اختاره، والخادم يمنعه من الوصول لأي ملف أو بيانات لطالب آخر. لكن أي شخص يملك الرابط يستطيع اختيار أي اسم، لذا شارك الرابط مع طلابك فقط.
- الملفات تُخزَّن بأسماء عشوائية (UUID) خارج المجلد العام، والاسم الأصلي يُنقّى ويُحفظ في القاعدة.
- الملفات تُقدَّم عبر مسار محمي بالصلاحيات، مع `Content-Disposition` و`nosniff` و`CSP: sandbox`. صفحات HTML وSVG وغيرها تُنزَّل كمرفقات ولا تُعرض، ولا يُنفَّذ أي ملف مرفوع.
- كل عمليات التعديل من حساب **المدير** ترجع **403** من الخادم، وأزرار التعديل مخفية في واجهته.
- ملفات CSV/Excel تُقرأ **في متصفح المعلم فقط**. الخادم يستخدم مكتبة `xlsx` لكتابة ملف التصدير فقط، وذلك تحوّطًا من ثغرات معروفة في قراءة الملفات بالمكتبة.
