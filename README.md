# 🏦 صندوق الإخوة

نظام سحابي لإدارة صندوق مغلق: اشتراكات شهرية، وسحوبات، وقروض بأقساط، ومصروفات، وتقارير، وكشف حساب لكل عضو.

| المسار | المحتوى |
|---|---|
| `app/` | التطبيق (React + Vite)، ويُنشر على GitHub Pages |
| `supabase/schema.sql` | قاعدة البيانات والصلاحيات؛ تُشغَّل مرة واحدة في Supabase |
| `sandooq-desktop.html` | النسخة القديمة؛ تبقى فقط لتصدير بياناتها ونقلها |

---

## خطوات التشغيل (مرة واحدة)

### 1) إنشاء قاعدة البيانات
1. افتح مشروعك في Supabase ← **SQL Editor** ← **New query**.
2. الصق محتوى `supabase/schema.sql` كاملاً، ثم اضغط **Run**.
3. يجب أن تظهر رسالة **Success**.

### 2) إعدادات الدخول في Supabase
من **Authentication**:
- **Sign In / Providers ← Email ← Confirm email: أوقفه.**
  خدمة البريد المجانية في Supabase لا ترسل رسائل التأكيد إلا لأعضاء فريق المشروع، فلن تصل للإخوة.
  إيقافه آمن هنا، لأن كل حساب جديد يبقى «بانتظار الموافقة» ولا يرى شيئاً حتى يعتمده المدير.
- **URL Configuration ← Site URL:** ضع رابط التطبيق، وهو `https://magid-alshahrani.github.io/my-apps/`، وأضفه كذلك في **Redirect URLs**.

### 3) تفعيل النشر على GitHub Pages
في المستودع على GitHub: **Settings ← Pages ← Source: GitHub Actions**.
بعدها يُنشر التطبيق تلقائياً مع كل دمج في `main`، بعد نجاح الاختبارات.

### 4) أول دخول
- **سجّل حسابك أنت أولاً** مباشرة بعد تشغيل الخطوة 1؛ أول حساب يُسجَّل يصبح **المدير**.
- من **الإعدادات**: اضبط شهر التأسيس ومبلغ الاشتراك.
- من **النسخ الاحتياطي**: انقل بيانات النسخة القديمة:
  1. افتح `sandooq-desktop.html` ← النسخ الاحتياطي ← تصدير البيانات.
  2. في التطبيق الجديد: النسخ الاحتياطي ← اختيار ملف.
- اطلب من الإخوة التسجيل، ثم من **الإعدادات ← المستخدمون** اعتمد كل حساب واربطه باسمه. اختر «أمين الصندوق» لمن يسجّل الحركات، و«عضو» للمشاهدة.

## الصلاحيات

| الدور | ماذا يستطيع |
|---|---|
| مدير | كل شيء: الإعدادات، والأسعار، والمستخدمون، والاستيراد، وإعادة فتح شهر مقفل |
| أمين الصندوق | تسجيل الدفعات والحركات والقيود العكسية، وإدارة الأعضاء، وإقفال الأشهر، والنسخ الاحتياطي |
| عضو | مشاهدة فقط، وكشف حسابه؛ يرى كل الحركات أو حركاته فقط حسب الإعداد |
| بانتظار الموافقة / موقوف | لا يرى أي بيانات |

الصلاحيات مفروضة داخل قاعدة البيانات (Row Level Security)، لا في الواجهة فقط.

## مبادئ الحماية المحاسبية
- **دفتر قيود لا يُحذف ولا يُعدَّل**، حتى من لوحة Supabase نفسها. التصحيح يكون بقيد عكسي مع ذكر السبب.
- **التحقق يتم في قاعدة البيانات**:
  - لا سحب أو قرض أو مصروف أكبر من الرصيد.
  - لا اشتراك أكبر من المستحق.
  - لا سداد أكبر من المتبقي على القرض.
- **مبلغ الاشتراك مؤرَّخ**: تغييره لا يؤثر على الأشهر السابقة.
- **الشهر المقفل** لا تُسجَّل فيه حركات جديدة.
- **سجل تدقيق** يسجّل كل عملية بصاحبها ووقتها، ولا يمكن تعديله.
- **الأعضاء يُؤرشفون ولا يُحذفون**، فتبقى سجلاتهم كاملة.

## تنبيهات
- الخطة المجانية في Supabase **توقف المشروع مؤقتاً بعد أسبوع بلا استخدام**. لا تضيع البيانات؛ افتح لوحة Supabase واضغط **Restore**.
- خذ **نسخة احتياطية مشفّرة** أسبوعياً من صفحة «النسخ الاحتياطي»، واحفظها في Google Drive أو iCloud. التطبيق يذكّرك بذلك.
- الاستيراد مسموح فقط على صندوق فارغ، ويتم كاملاً أو لا يتم إطلاقاً.

## للمطوّرين

```bash
cd app
npm install
npm test          # اختبارات الحسابات + اختبارات قاعدة البيانات على PostgreSQL حقيقي (PGlite)
npm run dev       # تشغيل محلي على Supabase الحقيقي
npm run build

# تشغيل الواجهة على قاعدة بيانات محلية داخل المتصفح (بدون لمس البيانات الحقيقية)
npx vite -c e2e/vite.config.js
```

- `src/config.js` فيه رابط Supabase والمفتاح العام (publishable). **لا تضع فيه مفتاح `secret` أو `service_role` أبداً.**
- `src/lib/`: منطق محاسبي خالص ومختبَر (الدفتر، والتواريخ، والنقل من النسخة القديمة، والتشفير).
