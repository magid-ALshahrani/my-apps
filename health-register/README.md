# سجل الموجه الصحي 1448هـ

نسخة رقمية تفاعلية من **«سجل الموجه الصحي 1448هـ»** و**«الخطة المشتركة للبرامج الصحية المدرسية 1448هـ»** (وزارة التعليم، الشؤون الصحية المدرسية).
تطبيق ويب عربي (RTL) يعمل على الجوال وسطح المكتب، وقابل للتثبيت كتطبيق (PWA)، بثيمين فاتح وداكن.

> البيانات صحية وتخص طلابًا قاصرين. التطبيق **لا يجمع ولا يخزن أي رقم هوية أو سجل مدني أو إقامة**، ولا يتصل بنظام نور.

| المسار | المحتوى |
|---|---|
| `src/` | الواجهة (React + Vite + TypeScript + Tailwind) |
| `supabase/migrations/` | قاعدة البيانات والصلاحيات (RLS) وسجل التدقيق، بالترتيب |
| `supabase/functions/admin-users/` | دالة إدارة المستخدمين (الموجه الصحي فقط) |
| `scripts/` | إنشاء الموجه الأول، البيانات التجريبية، بيئة الاختبار المحلية |
| `tests/` | اختبارات الوحدة، وقاعدة البيانات، والواجهة |
| `docs/` | ملفا المصدر الرسميان (PDF) |

---

## الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| **الموجه الصحي** | كل الصلاحيات، ودعوة المستخدمين وتحديد أدوارهم وتعطيلهم، والإعدادات، والوحيد الذي يحذف، والوحيد الذي يفتح سجل العنف الأسري (بإعادة إدخال كلمة المرور). |
| **مدير/ة المدرسة** | قراءة كل شيء عدا سجل العنف الأسري، واعتماد التقارير ومحاضر اللجنة ونماذج التفقد. لا يعدّل الحالات ولا يحذف. |
| **ممرض/ة العيادة** | قراءة الطلاب، وقراءة وكتابة الحالات والسجلات الرسمية والزيارات والتحويلات وبيانات العيادة، وقراءة البرامج. |
| **عضو اللجنة** | قراءة البرامج والتقويم وخطة المتابعة، وتحديث حالة التنفيذ وإضافة الشواهد، وإحصاءات مجمّعة (أعداد فقط). لا يرى أسماء الطلاب ولا حالاتهم. |

الصلاحيات مفروضة في قاعدة البيانات (RLS) على كل جدول، والدور يُقرأ من جدول `profiles` عبر دالة `SECURITY DEFINER`؛ إخفاء القوائم في الواجهة للتجربة فقط.

## التشغيل لأول مرة

### 1) إنشاء مشروع Supabase
1. أنشئ مشروعًا جديدًا في [supabase.com](https://supabase.com) (اختر منطقة قريبة).
2. من **Project Settings ← API** انسخ: `Project URL` و`anon public key`. (مفتاح `service_role` لا يوضع في الواجهة أبدًا.)

### 2) إنشاء قاعدة البيانات
**الطريقة أ (لوحة Supabase):** من **SQL Editor** شغّل ملفات `supabase/migrations/` واحدًا تلو الآخر **بالترتيب**:
`20261003000001_core.sql` ← `…02_rls.sql` ← `…03_functions.sql` ← `…04_reference_data.sql`.

**الطريقة ب (Supabase CLI):**
```bash
npx supabase login
npx supabase link --project-ref <معرّف-المشروع>
npx supabase db push
```

### 3) إعدادات الدخول (Authentication)
- **Sign In / Providers ← Email:** أوقف **Allow new users to sign up** (لا تسجيل ذاتي؛ الحسابات من الموجه فقط).
- **Password:** اجعل **Minimum password length = 10**.
- **URL Configuration ← Site URL:** رابط التطبيق بعد النشر.

### 4) نشر دالة إدارة المستخدمين
```bash
npx supabase functions deploy admin-users
# اختياري: تقييد المصدر المسموح
npx supabase secrets set ALLOWED_ORIGIN=https://رابط-تطبيقك
```
الدالة تقرأ `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` تلقائيًا من بيئة Supabase، وتتحقق أن المنادي **موجه صحي نشط** قبل أي عملية.

### 5) إنشاء حساب الموجه الصحي الأول (مرة واحدة)
على جهازك فقط (لا ترفع المفتاح لأي مكان):
```bash
npm install
SUPABASE_URL=https://xxxx.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=<service_role من لوحة Supabase> \
GUIDE_EMAIL=you@example.com GUIDE_NAME="اسم الموجه" \
npm run create-guide
```
يطبع كلمة مرور مؤقتة **مرة واحدة**، ويُلزمك بتغييرها (10 أحرف على الأقل) عند أول دخول.

**بديل من اللوحة:** Authentication ← Users ← Add user (مع Auto Confirm)، ثم في SQL Editor:
```sql
insert into public.profiles (id, email, full_name, role, must_change_password)
select id, email, 'اسم الموجه', 'health_guide', true from auth.users where email = 'you@example.com';
```

بقية المستخدمين يضيفهم الموجه من داخل التطبيق: **المستخدمون ← دعوة مستخدم** (تظهر كلمة مرور مؤقتة مرة واحدة). عضو اللجنة يُسجَّل تلقائيًا أيضًا في سجل تشكيل اللجنة.

### 6) متغيرات البيئة للواجهة
انسخ `.env.example` إلى `.env`:
```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=<anon public key>
```
الملف `.env` مستثنى في `.gitignore`.

### 7) التشغيل محليًا
```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # فحص الأنواع + بناء الإنتاج في dist/
```

## النشر

### Vercel
1. استورد المستودع، واجعل **Root Directory = `health-register`**.
2. أضف متغيري البيئة `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
3. الإعدادات في `vercel.json` (توجيه الصفحات وترويسات أمان). انشر.

### Netlify
1. **Base directory = `health-register`**، والأمر والمخرجات من `netlify.toml`.
2. أضف متغيري البيئة نفسيهما، ثم انشر.

بعد النشر ضع رابط التطبيق في **Site URL** في Supabase.

> ملاحظة أمنية: حزمة `xlsx` على npm (0.18.5) عليها تنبيهات معروفة، والإصدار الأحدث من SheetJS يُنزَّل من موقعهم. قبل النشر يُنصح بتشغيل:
> `npm i https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`
> (لم يُطبَّق هنا لأن ذلك النطاق محجوب في بيئة التطوير.)

## استيراد قائمة الطلاب من «نور»

التطبيق **لا يتصل بنور** ولا يطلب بيانات الدخول إليه. أنت تصدّر الملف بنفسك:
1. ادخل نظام نور، ثم من تقارير الطلاب اختر **كشف أسماء الطلاب** (حسب الصف والفصل أو للمدرسة كاملة).
2. صدّره بصيغة **Excel** واحفظه على جهازك.
3. في التطبيق: **استيراد القوائم ← قائمة الطلاب ← قالب «نور»** ثم اختر الملف.
4. يكتشف المعالج صف العناوين (حتى مع سطور الشعار والخلايا المدمجة)، ويربط الأعمدة تلقائيًا، وتراجع أنت الربط والتكرارات والفصول الجديدة، ثم تؤكد.

**حماية الهوية:** أي عمود هوية (بعنوانه أو بمحتواه: 60% من قيمه تطابق 10 أرقام تبدأ بـ 1 أو 2) يُحذف **داخل المتصفح** قبل أي معاينة أو إرسال، ويظهر في المعاينة بعنوانه فقط بشارة «لن يُحفظ». أي رقم بهذا النمط داخل نص آخر يُستبدل بـ «[محذوف]» (في الواجهة، ومرة أخرى في قاعدة البيانات). الملف الأصلي لا يُرفع ولا يُحفظ.

يقبل المعالج أيضًا: csv وxls وdocx، وقالبًا مخصصًا، وقالب قوائم أعضاء اللجنة. يمكن حفظ ربط مخصص كقالب (أسماء الأعمدة فقط).

## الاختبارات والتحقق

| الأمر | ما يفحصه |
|---|---|
| `npm test` | محللات الاستيراد (xlsx/xls/csv/docx)، قالب نور، حماية الهوية، OCR والعروض، التصدير، وعدم وجود أعمدة هوية |
| `npm run stack` ثم `npm run test:db` | RLS لكل دور، Edge Function، التدقيق، قيود حالة التنفيذ، «متأخر التحديث»، المخزن والروابط الموقّعة |
| `node tests/e2e/import-protection.mjs` | استيراد عبر الواجهة ثم البحث عن الهويات الوهمية في الشبكة وكل الجداول والتدقيق والمخزن |
| `node tests/e2e/phase3.mjs` | السجلات والبرامج والشواهد وOCR والصلاحيات في الواجهة |
| `node tests/e2e/exports.mjs` ثم `verify-exports.mjs` | تصدير PDF/Word/Excel وفحص العربية والاتجاه |
| `node tests/e2e/security.mjs` | إلزام تغيير كلمة المرور، القفل بعد 15 دقيقة، خلو الحزمة من مفتاح الخدمة |
| `node tests/e2e/screens.mjs` | لقطات 375px و1280px في الثيمين مع فحص RTL والتباين (4.5:1) |

اختبارات الواجهة تتطلب: `npm run stack` (بيئة محلية تحاكي Supabase: Postgres + GoTrue + PostgREST)، والبيانات التجريبية، و`npm run dev`، ومتغير `DEMO_PASSWORD`.

## الأمان باختصار
- RLS مفعّل ومفروض (`force`) على كل الجداول؛ غير المصادَق لا يرى شيئًا.
- لا تسجيل ذاتي؛ كلمة مرور مؤقتة مع إلزام التغيير (10 أحرف على الأقل).
- قفل تلقائي بعد 15 دقيقة خمول.
- سجل العنف الأسري: الموجه فقط، وقاعدة البيانات نفسها تشترط تسجيل الدخول بكلمة المرور خلال آخر 10 دقائق.
- `audit_log` لكل إضافة/تعديل/حذف: المستخدم ودوره والجدول والعملية والوقت وأسماء الأعمدة المعدّلة — **بلا محتوى البيانات**.
- مخزن الملفات خاص، وروابط موقّعة مؤقتة، ورفض الأنواع غير المدعومة والملفات فوق 10 ميجابايت، وفحص الجداول بحثًا عن أرقام الهوية قبل الرفع.
- OCR يعمل داخل المتصفح بملفات مستضافة مع التطبيق (`public/ocr`)، بلا خدمة خارجية.
